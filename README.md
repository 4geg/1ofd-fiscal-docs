# 1OFD Fiscal Docs 1.7.8

Локальное приложение для выгрузки фискальных документов через Universal API Первого ОФД. Автор: **4geg**.

## Изменения 1.7.8

- В настройках добавлен отступ между выбором профиля и кнопкой его применения. В интерфейсе используется название «результаты запросов»; ручная очистка удаляет всю историю вместе с текущим результатом.

- В карточке скрываются только явно перечисленные нулевые суммы способов оплаты, комиссий и положительных ставок НДС. НДС 0%, итог чека, количество/цена/сумма позиции, ставки, признаки и неизвестные реквизиты сохраняются. Позиции не удаляются. Исходный JSON остаётся полным.
- Реквизиты Universal API получили русские названия, включая НДС 22%, постоплату, маркировку и данные агента. Исходное имя доступно в подсказке; неизвестные реквизиты находятся в «Дополнительных данных ФД».
- CSV включает прежние основные колонки и реквизиты всех документов выбранного результата с русскими заголовками. Нули в CSV сохраняются. Первый проход определяет полный набор колонок, второй записывает строки; документы не собираются в общий массив. Неизвестные пути API сохранены в служебной колонке. JSON-экспорт не менялся.
- История хранит текущий и предыдущий результаты запросов. Если их уникальные файлы индекса и JSON-архивов вместе превышают 5 ГБ (5 × 1024³ байт), предыдущий удаляется. Один текущий результат любого размера сохраняется полностью. Общие архивы учитываются один раз и удаляются только после исчезновения всех ссылок.
- В трее и в веб-настройках есть «Удалить все результаты запросов» с подтверждением. Удаляются предыдущий и текущий результаты, данные восстановления и ручного добора. Активный поиск или перенос сначала останавливается. Открытая карточка или экспорт удерживает используемые файлы до завершения, затем отложенная очистка повторяется автоматически. Очистка из трея также убирает результат из открытого веб-интерфейса.
- Шестерёнка **НАСТРОЙКИ** в шапке открывает секции «Нагрузка», «Хранение истории», «Логирование». Профили, ручные параметры и лимит журнала перенесены из трея; параллелизм убран из фильтра и задаётся в одном месте. Сохранение ручных настроек и отметки профиля продолжают работать.
- «Завершить» в трее снимает иконку и немедленно завершает процесс через `os._exit(0)` без ожидания потоков. В журнал записываются принудительный выход и число активных HTTP-запросов. Незавершённый поиск обрывается; последний опубликованный результат остаётся на диске.
- Схема запуска, single-instance, перезапуск сервера в том же процессе, порты 4784–4803, 30 дней, повторы 120 → 24 → 6, полнота и правила GitHub Actions сохранены. 1.7.7 выпущена 10.10.2026; новый номер — 1.7.8.

## Изменения 1.7.7

- SQLite содержит компактный индекс, а полные JSON находятся в отдельных `.raw`-архивах: каждый документ — самостоятельная gzip-запись. Индекс содержит имя архива, смещение и длину записи. Карточка читает один документ; JSON/CSV экспортируют всю отфильтрованную выборку потоком.
- Явно установлены `journal_mode=DELETE` и `synchronous=FULL`. Сырые HTTP-ответы не попадают в SQLite. Запись JSON сохраняется на диск до фиксации её ссылки в базе.
- Большая база формата 1.7.6 переносится в фоне: интерфейс запускается, прежние документы доступны. Проверяется количество ФД; переключение `last_search.json` атомарное. При ошибке или остановке переноса исходный результат остаётся. Для переноса требуется свободное место под новый индекс и архивы до удаления старой базы.
- Ручной добор копирует только индекс, используя существующие неизменяемые архивные записи. Результат не урезается. Автоматическая очистка сохраняет текущий и предыдущий результаты, а также результаты активных выгрузок. Явное удаление всех результатов очищает и текущий. Удаляются архивы, на которые больше нет ссылок.
- Пресеты переименованы: **Минимальный / Средний / Высокий / Максимальный**. По умолчанию — **Средний**, с промежуточными ответами на диске.
- Под пресетами в трее добавлены **Ручные настройки**: текущие значения, готовые варианты и форма для ввода произвольных чисел. Все параметры сохраняются. Ручное изменение помечает исходный профиль как «изменён вручную»; выбор пресета явно возвращает его значения.
- `tools/make_icon.py` принимает квадратный PNG и создаёт ICO с несколькими размерами. `build_exe.bat` применяет корневую `app.ico` одновременно к EXE, трею и favicon.
- Версия программы, шапки, сборки и метаданных EXE поднята до **1.7.7**. 1.7.6 не публиковалась отдельным релизом.

### Параметры пресетов

| Параметр | Минимальный | Средний (по умолчанию) | Высокий | Максимальный |
| --- | ---: | ---: | ---: | ---: |
| Одновременных запросов, максимум | 30 | 120 | 160 | 200 |
| Лимит промежуточной памяти, МБ | 32 | 64 | 256 | 512 |
| Кэш базы на соединение, МБ | 2 | 4 | 8 | 16 |
| Временные ответы | На диск | На диск | Смешанный | В память |
| Блок чтения ответа, КБ | 16 | 32 | 64 | 128 |
| Строк на странице, максимум | 100 | 200 | 500 | 1000 |

Параллелизм и хранение задаются независимо. Параллелизм задаётся только в НАСТРОЙКИ → Нагрузка. Активный поиск фиксирует настройки при старте; изменения действуют на следующий поиск/добор. Новый просмотр использует текущие кэш и размер страницы.

Лимит промежуточной памяти — общий для буферов HTTP-ответов одного поиска, а не для каждого ответа и не для всей памяти процесса. «Смешанный» держит в памяти до 8 МБ на отдельный ответ в пределах общего лимита. «В память» может использовать весь общий лимит; переполнение любого ответа переносится на диск без обрезки. Полученные документы всегда сохраняются на диск. SQLite-сортировки используют временные файлы при всех профилях. «Максимальный» осознанно повышает расход памяти.

## Как пользоваться

Добавьте API-ключ, выберите период и типы ФД. Верхняя панель задаёт запрос к ОФД; нижняя фильтрует весь полученный результат через локальный сервер. Страница таблицы ограничивает только отображение, не выборку и не экспорт.

Несколько условий вводятся через `;` и Enter. CSV-фильтр находится под шестерёнкой каждой панели; импорт применяется туда, откуда открыт, и сам не запускает API-запрос. Ошибочные строки объясняются и пропускаются.

Сброс в шапке: **Сброс [↻ Фильтры | ↻ Всё | ↻ Результат]**. Подтверждение требуется только для «Всё». Сброс результата скрывает список, сохраняя возможность явно восстановить последний поиск.

## Что умеет

- Регистрация, перерегистрация, закрытие ФН; чеки, коррекции, БСО, открытие/закрытие смены.
- Запросы за период до **30 дней**. Автоматической разбивки на 31 день нет.
- Добор неудачных заданий по схеме **120 → 24 → 6**, с дополнительным пределом нагрузки и ручным повтором.
- Отдельный контроль полноты; неполный каталог ККТ не кэшируется.
- Карточка с полным исходным JSON, копированием реквизитов и открытием в новой вкладке.
- Восстановление результата и retry-контекста после закрытия вкладки/перезапуска.
- Три файла журнала по размеру; лимит из веб-настроек применяется к каждому файлу.
- Один Windows EXE со встроенными ресурсами. Python на компьютере пользователя не нужен.
- Кнопка версии ведёт на GitHub; новый стабильный релиз отмечается красным `!`. Публичная проверка не чаще раза в 6 часов; автообновления нет.

## Запуск и сборка

Исходники: установить зависимости из `requirements.txt`, затем запустить `python main.py`. Для Windows-сборки используется `build_exe.bat`; результат — `dist/1OFD_FiscalDocs.exe` и `dist/SHA256SUMS.txt`. Сборка содержит все ресурсы; папка `assets` рядом с готовым EXE не нужна.

`tools/pack_resources.py` регенерирует `resource_bundle.py` перед локальной сборкой. Для прямой CI-сборки актуальный сгенерированный модуль должен быть включён в коммит. Существующие Actions и проверка Author/Committer не изменяются.

## Где хранятся данные

`%APPDATA%\4geg\1OFD_Fiscal_Docs\`:

- `config.json` — сохранённые API-ключи, на Windows защищённые DPAPI;
- `runtime_settings.json` — пресет и независимые ручные параметры;
- `ofd_kkm_cache.json` — только полный каталог ККТ;
- `last_search.json` — метаданные, ID результата и retry-контекст без секретов;
- `result_history.json` — ID текущего и предыдущего результатов, атомарно сохранённые перед очисткой;
- `results/*.sqlite` — компактные индексы; `results/*.raw` — архивы полных JSON;
- `resources/` — управляемые встроенные шрифты, документы и иконки;
- `update_check.json` — кэш проверки версии;
- `logs/app.log`, `.1`, `.2` — текущий журнал и два предыдущих.

Индекс, JSON-архивы и `last_search.json` составляют единый результат: не удаляйте их по отдельности. Большая полная выборка по-прежнему требует места на диске. Автоматического VACUUM и жёсткой квоты ФД нет.

## Безопасность и ограничения

Сервер слушает `127.0.0.1`; предпочтительный порт 4784, резервные 4785–4803. Приложение не должно требовать права администратора. API-ключи не записываются в поиски или журналы. Подписывание EXE сертификатом не реализовано.

Регистрация — синтетический тип по `fiscalReport`: при недостаточных сведениях о жизненном цикле ФН полнота не гарантируется, UI должен сообщать об этом. Ошибка API-проверки не равна ошибке внутри чека.
