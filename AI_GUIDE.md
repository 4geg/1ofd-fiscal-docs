Мягкий порог — `HISTORY_SOFT_LIMIT_BYTES = 5 * 1024**3`: удалить предыдущий при превышении, никогда не уменьшать текущий. При первом переходе с 1.7.7 выбирается один предыдущий индекс; остальные удаляются при безопасной проверке ссылок.
- `RESULT_WRITERS` защищает создаваемые индексы и оба пакета во время уплотнения вплоть до публикации/отмены. Только GC с `publish_current=True` после успешного persist_search_state снимает защиту current/previous; закрытие экспорта в промежутке LAST_RESPONSE → atomic last_search не должно удалить последний сохранённый снимок. `RESULT_READERS` удерживает экспорт/карточку; `HISTORY_PENDING_DELETIONS` повторяет GC после закрытия последнего читателя. Не читать GC-индексы через `DiskRows.connect()`: это создало бы рекурсивные reader lease. Ошибка чтения/отсутствующий архив — отложить GC.
- `/api/history`, `/api/history/clear` показывают фактический объём/число результатов запросов. Очистка с `confirmed: true` удаляет ВСЕ результаты, включая current, last_search/retry context и промежуточные данные. HISTORY_CLEARING запрещает запуск нового поиска/добора; активная задача отменяется и завершается до удаления под SEARCH_LOCK. finish_storage_work дожидается работы с диском даже при отмене: поздняя запись не должна восстановить удалённый результат. STATE.history_revision синхронизирует открытые вкладки с очисткой из трея. API-ключ snapshots оставлен для совместимости, пользователь видит «результаты запросов». Трей вызывает этот же endpoint после Windows MessageBox; веб использует confirm. Cached `HISTORY_LAST_INFO` предотвращает блокировку нативного трея SQL-сканированием.
- Настройки только в вебе: `settingsBtn` → `loadSettingsModal`, секции нагрузки/истории/логирования. `/api/load-settings` принимает отдельно preset, manual values или log_limit_mb, не смешивать их. Изменение журналов не должно сбрасывать manual_modified. Listener в main.py применяет новый лимит к SizeLimitedLogHandler.
- Старое поле SearchRequest.concurrency оставлено для чтения retry-контекста и совместимости API; реальный новый поиск берёт get_load_profile()['concurrency_cap'] при старте. В HTML/JS нет qConcurrency. Активный поиск использует свой snapshot настроек.
- Явный `exit_app` использует `os._exit(0)`: прямое дописывание одной строки в журнал без locks logging, active HTTP counter, скрытие значка, native `_stop()` (public Icon.stop() может ждать setup thread), закрытие server socket/runtime/mutex. Не добавлять graceful wait/join в этот путь. `TrackedAsyncClient` / `ActiveResponseStream` считают запрос до закрытия потокового ответа; завершение сокетов делает ОС.
- Перезапуск через `_stop_server` остаётся прежним. Нельзя заменять его принудительным выходом или вторым frozen EXE. Forced exit сохраняет опубликованный DELETE/FULL snapshot, но не завершает прерванный запрос; startup GC убирает его мусор после проверки живых ссылок.

## Путь ФД и сохранность

HTTP → IntermediateBuffer → DocumentStream/ijson → один нормализованный ФД → gzip-запись → компактный индекс.

- `read_json_without_array` читает служебные метаданные без массива documents. `python_json_numbers` сохраняет произвольно большие целые ID; дробные значения соответствуют прежнему json.load. Некорректный documents — ошибка задания, не полный пустой результат.
- `DocumentStore.add` дедуплицирует по прежнему ключу РНМ/ФН/ФД/тип. raw пишется потоковым encoder + gzip level 1. Каждая ссылка фиксируется только после flush/fsync файла. Транзакции индекса — до 128 записей, DELETE и synchronous FULL. Не отключать journal/synchronous ради скорости.
- `DiskRows.detail` читает ровно одну gzip-запись через BoundedRawReader: нельзя дать gzip прочитать следующий member. Карточка материализует только один документ. Экспорт JSON декомпрессирует записи блоками; не собирать весь Blob/строку/массив.
- При ручном доборе backup копирует только SQLite-индекс. Архивные ссылки могут вести на пакеты более раннего store_id: **не удалять raw по возрасту/имени текущей базы**.
- При автоматической уборке `cleanup_result_stores` сохраняет текущую, предыдущую (если укладываются вместе в мягкий лимит 5 ГБ) и используемые читателями базы. `ResultConnection` учитывает открытые карточки/экспорты; mark-and-sweep удаляет только raw без ссылок из оставшихся баз. Если проверить ссылки не удалось, очистку архивов отложить.
- Перезаписанные записи нового архива уплотняются только если мусор ≥16 МБ и ≥30% файла, до публикации снимка. Новые смещения фиксируются после сохранения нового пакета. Старый пакет удаляется только после успешного commit. Не уплотнять разделяемые старые пакеты с чужими живыми ссылками.
- VACUUM автоматически не запускать. SQLite новой схемы создаётся компактным; восстановление старой схемы создаёт новую базу, не оставляя её старые raw-страницы. Совокупный объём на диске зависит от полной выборки и сохранённых снимков.
- `last_search.json` содержит store_id, метаданные и failed tasks, записывается потоково/атомарно. Старый массив rows поддерживается поштучным переносом; старый SQLite raw переносится в фоне. `published` защищает готовый новый снимок от удаления при поздней отмене миграции.
- Все три компонента — индекс, архивы и last_search — единый результат. Старую версию нельзя использовать для отката без резервной копии пользовательских данных: новый формат ей неизвестен.

## Профили и ручные параметры

Истина — `LOAD_PROFILES` / `MANUAL_SETTING_LABELS` / `MANUAL_SETTING_RANGES` в config_store.py. Режим хранения относится к промежуточным HTTP-ответам; долговременный результат всегда на диске. Mixed: до 8 МБ на ответ, общий бюджет обязателен. Memory: общий бюджет, затем spill. SQL temp_store=FILE при всех режимах, иначе сортировка огромной выборки могла бы обойти лимит HTTP-памяти.

Кэш SQLite задаётся на соединение; HTTP-буферы — суммарно на поиск. Это не жёсткий RSS-лимит: остаются каталог, активные документы, одиночная карточка, сетевые/декомпрессионные буферы и Python overhead. Профиль фиксируется в SEARCH_PROFILE на начало поиска/добора. Для будущих читателей берутся актуальные значения. Не менять параметры активного поиска посередине.

## Поиск, условия и типы

Типы: registration (синтетический fiscalReport), reregistration, close, ticket, open_shift, close_shift, receipt_correction, bso, bso_correction. API transactionTypes не выдумывать. Регистрация по жизненному циклу ФН: недостаточные даты должны отражаться в статусе полноты.

Верхние ручные chips фильтруют каталог ККТ. Типизированные ФД/ФПД/смена проверяются после получения документов; их наличие расширяет предварительный отбор, сохраняя расширенные AND-ограничения. Условия ФН сужают конкретный ФН. Chips/typed conditions — OR, расширенные поля — AND.

Ручной ввод разделяется только по `;`, не по запятой адреса. CSV type;completeness;data: UTF-8/BOM и Windows-1251, quoted/multiline, до 2 МБ / 10 000 строк. Неизвестный type, пустой data, битые строки объясняются и пропускаются. РНМ/ЗН/ФН — строки с ведущими нулями; ФПД чувствителен к регистру. Full — равенство, partial — подстрока.

Импорт фиксирует панель открытия, выбора панели нет. Верхний импорт не запускает поиск; нижний обращается только к локальному серверу. query_conditions сохраняются один раз в meta.request без секретов; failed tasks используют общую query_request и восстанавливают её.

## UI, карточка и восстановление

Сброс: подпись + ↻ в трёх зонах; подтверждение только «Всё». last_search остаётся, sessionStorage скрывает сброшенный результат до явного восстановления. Поколения запросов/AbortController защищают список/карточку от запоздалых ответов.

Noto Sans OFD через локальный @font-face с Segoe UI/Arial fallback; JSON — Consolas/Courier New. Размеры карточки 17/21/25 px, правое выравнивание и центрированные разделы. RECEIPT_EQUALS_FIELDS — явный список только кодовых/числовых полей; даты/время/адреса/ФИО/статусы без `=`, двоеточия сохранены. Копирование возвращает значение без `=`/подписи. Адрес — выделение/Ctrl+C.

Основные данные, закрытые «Дополнительные данные ФД» и «Полный ответ API» сохранять. Все raw.document поля сохраняются; денежные нули из явного списка скрываются только в карточке. `?doc=...&result=...` использует дисковый снимок. Sticky headers непрозрачные; select focus использует background-color, не background shorthand; scrollbar находится в modal-body, не на скруглённом modal-box.

pystray в главном потоке; сервер стартует после готовности tray event-loop и ждёт HTTP health, не только TCP. Долгие callback-и работают в worker threads. Открытие/рестарт и формат runtime.json сохранять; явный выход принудительный, файл runtime удаляется перед завершением. Логи: app.log/.1/.2 по размеру, лимит каждого 1/5/10/25/50 МБ, без ротации по времени.
