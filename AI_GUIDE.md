# AI GUIDE — 1OFD Fiscal Docs

Версия проекта: **1.7.3**  
Автор: **4geg**

Этот файл предназначен для разработчика или нейросети, которые впервые открыли проект. Перед изменениями прочитать полностью.

## 1. Назначение

Локальное Windows-приложение для массового поиска фискальных документов в Universal API Первого ОФД. Backend написан на Python/FastAPI, UI встроен в `ofd_app.py` как HTML/CSS/JS. Пользователь работает в обычном браузере, а само приложение остаётся запущенным в системном трее.

## 2. Структура

- `main.py` — точка входа desktop-приложения, tray, запуск Uvicorn, повторный запуск, single-instance.
- `ofd_app.py` — FastAPI backend, вся бизнес-логика 1-ОФД и встроенный веб-интерфейс.
- `config_store.py` — хранение настроек, списка API-ключей и Windows DPAPI.
- `version.py` — имя, версия, автор, host/port.
- `requirements.txt` — runtime-зависимости.
- `build_exe.bat` — сборка Windows EXE через PyInstaller.
- `run_dev.bat` — запуск из исходников для новичка.
- `assets/app.ico` — единая иконка EXE и системного трея. Сборка не должна перезаписывать существующую пользовательскую иконку.
- `tools/make_icon.py` — пересоздание базовой иконки.
- `.github/workflows/build-windows.yml` — CI-сборка Windows EXE.

## 3. Ключевые правила

1. **Никогда не вшивать API-ключ в исходники.**
2. **Никогда не логировать полный API-ключ, Authorization или токен.**
3. Не ухудшать контроль полноты ради скорости.
4. Не удалять повторные попытки HTTP-запросов без веской причины.
5. Не сохранять неполный каталог ККТ в кэш.
6. После изменения фильтрации обязательно проверить сценарии: весь парк, конкретный РНМ, конкретный ФН, несколько query chips.
7. UI запроса к API и UI локальной фильтрации должны оставаться визуально похожими, но логически независимыми.

## 4. API-ключи

Пользователь может сохранить несколько ключей.

Endpoints:
- `GET /api/keys`
- `POST /api/keys/add`
- `POST /api/keys/select`
- `DELETE /api/keys/{id}`

При добавлении ключ валидируется прежде всего успешной авторизацией через `/api/auth`. Получение названия организации выполняется вторым запросом, но его временный сбой не должен отклонять уже авторизованный ключ. Для frozen EXE `httpx` создаётся с явным CA bundle `certifi.where()`, а сборка обязана включать `--collect-data certifi`.

На Windows секрет шифруется DPAPI текущего пользователя. В `config.json` нельзя хранить открытый ключ. Локальный endpoint reveal используется только для показа ключа в localhost UI; его значение нельзя логировать, сохранять в JS storage или отправлять наружу. UI автоматически снова скрывает раскрытый сохранённый ключ.

Токен Universal API живёт около 2 часов. Программа обновляет его примерно через 110 минут. `TOKEN_CACHE` разделён по ID сохранённого профиля, чтобы переключение ключей не смешивало токены.

## 5. Основной алгоритм поиска

Общий поток:

1. Авторизация по выбранному API-ключу.
2. Получение организации.
3. Получение/чтение из кэша каталога ККТ.
4. Применение фильтров запроса до API.
5. Построение кандидатов РНМ + ФН.
6. Формирование минимального набора document tasks.
7. Основной параллельный проход.
8. Автоматический повтор только неудачных запросов с меньшей параллельностью.
9. Финальный медленный повтор.
10. Нормализация и deduplicate результатов.
11. Отдельный статус полноты.

`DEFAULT_DOCUMENT_CONCURRENCY = 120`, но пользователь может изменить в UI. Высокие значения не гарантируют больший throughput: сервер может начать чаще сбрасывать соединения.

## 6. Типы документов

Внутренние ключи проекта:
- `registration`
- `reregistration`
- `close`
- `ticket`
- `open_shift`
- `close_shift`
- `receipt_correction`
- `bso`
- `bso_correction`

Для большинства типов используется `transactionTypes` Universal API.

`registration` — специальный синтетический тип. У API нет отдельного `transactionTypes` для первичной регистрации. Программа ищет `fiscalReport` по ФН, активированным в выбранный период. Если activationDate ненадёжна, UI должен показывать предупреждение об ограничении полноты.

## 7. Полнота

Счётчик неудачных запросов — это не ошибка внутри чека, а HTTP/API-проверка, которая не завершилась успешно даже после повторов.

Нельзя показывать пользователю «выборка полная», если:
- есть `failed_tasks`;
- не полностью загружен каталог ККТ;
- при поиске регистрации есть ФН с недостаточной информацией для гарантированной проверки.

При временных сетевых сбоях повторяются только неудачные задания, а не весь парк.

## 8. Кэш

`ofd_kkm_cache.json` хранится в `%APPDATA%`, а не рядом с EXE. Это важно для PyInstaller `--onefile`, который запускается из временного каталога.

Неполный каталог не кэшировать.

## 9. UI

Текущий визуальный стиль:
- без явных обводок;
- голубая палитра;
- очень сильные скругления;
- поисковые условия создаются chips по Enter;
- несколько chips означают несколько допустимых значений;
- расширенные точные фильтры применяются дополнительно;
- help `!` расположен внутри поля/контрола, перед `+` или стрелкой;
- tooltip должен появляться быстро и быть поверх интерфейса;
- не возвращать длинные пояснения под полями, если их можно вынести в help.

Верхний блок реально меняет API-запрос. Нижний блок фильтрует только уже полученные данные и не должен делать сетевые запросы.

## 10. Tray и lifecycle

`main.py`:
- создаёт single-instance mutex;
- запускает Uvicorn в daemon-thread;
- открывает браузер после readiness check;
- запускает `pystray` в главном потоке;
- меню: Открыть / Перезапустить / Завершить.

Повторный запуск EXE не должен создавать второй сервер — он должен открыть существующий UI.

## 11. Runtime paths

Постоянные данные:

`%APPDATA%\4geg\1OFD_Fiscal_Docs\`

Логи:

`...\logs\app.log`

Не использовать путь к исходному `.py`/EXE для runtime config/cache.

## 12. Перед коммитом

Минимальные проверки:

```powershell
python -m py_compile main.py ofd_app.py config_store.py version.py
```

Также проверить JavaScript внутри HTML (при наличии Node.js можно извлечь `<script>` и выполнить `node --check`).

Ручные проверки:
- первый запуск без ключа;
- добавить ключ;
- перезапуск и повторный выбор сохранённого ключа;
- удалить ключ;
- поиск за известный период;
- 0 непроверенных запросов;
- локальная фильтрация;
- CSV/JSON экспорт;
- закрыть вкладку и открыть из tray;
- повторный запуск EXE при уже работающем приложении;
- Перезапустить из tray;
- Завершить из tray.

## 13. Не реализовано намеренно

Прямой URL на ФД в личном кабинете 1-ОФД требует внутренний ID ККТ. Внутренний `cp-ofd` API использует browser Cookie + XSRF. Не пытаться сохранять или копировать browser session secrets в приложение без отдельного решения и оценки безопасности.


### Windows launcher / tray

`main.py` запускает `pystray` в главном потоке. Сервер стартует из `TRAY.run(setup=...)`, то есть после готовности tray event-loop; это важно для надёжного первого автооткрытия браузера. Uvicorn работает в отдельном daemon-потоке. Все callback-и трея, которые могут ждать I/O, обязаны запускать worker thread и не блокировать UI-поток `pystray`. Готовность сервера проверяется HTTP-запросом к `/api/health`, а не только открытым TCP-портом. Предпочтительный порт — 4784; при конфликте выбирается следующий свободный порт из диапазона 4784–4803 и записывается в `%APPDATA%/4geg/1OFD_Fiscal_Docs/runtime.json`. При повторном запуске второй экземпляр читает runtime-файл и открывает уже работающий интерфейс. Перезапуск сервера в v1.7.3 выполняется внутри того же процесса — нельзя возвращать схему с запуском второго frozen EXE, потому что для PyInstaller onefile это может оставлять заблокированный `_MEI`-каталог и давать `Failed to remove temporary directory`.

Если EXE показывает иконку трея, но интерфейс не открывается, первым делом открыть в меню трея `Открыть журнал`. Основной лог: `%APPDATA%/4geg/1OFD_Fiscal_Docs/logs/app.log`.


## Изменения 1.7.3, которые нельзя случайно сломать

- Активный `/api/search` и `/api/retry-failed` сохраняют `asyncio.current_task()` в `ACTIVE_SEARCH_TASK`. Endpoint `/api/stop-search` вызывает `cancel()` этой задачи. `CancelledError` обрабатывается отдельно и не должен превращаться в HTTP 500.
- Поля `date`, `inserted_at`, `activation_date`, `close_archive_date`, `expire_date` — человекочитаемые (`ДД.ММ.ГГГГ ЧЧ:ММ`). Для логики сортировки/фильтрации используются отдельные `date_sort`, `inserted_at_sort`, а исходные значения сохраняются в `*_raw`. Не фильтровать по отображаемой строке `ДД.ММ.ГГГГ`.
- Карточка документа формирует `currentDetailValues`; кнопки `.detail-copy` копируют именно отображаемое значение, а `raw` JSON остаётся неизменённым.
- Пункт трея «Скопировать ссылку интерфейса» копирует текущий `CURRENT_WEB_URL`, а не жёстко заданный порт 4784: порт может измениться при конфликте.
- В пользовательских текстах использовать термин «фискальные документы», не «финансовые документы».


### Раздельные дата и время в карточке ФД (v1.7.3)
В таблице дата/время по-прежнему хранятся как одна строка для сортировки и компактности, но в модальном окне карточки значения `ДД.ММ.ГГГГ ЧЧ:ММ` разбиваются на два визуальных поля. У каждого поля собственная кнопка копирования. Не объединять их обратно без явного требования.
